# 安全边界与增量更新

## 1. 私有代码与敏感信息

- 默认在本地工作区分析，不上传代码。
- 不把仓库内容粘贴到外部网站、在线代码分析器或第三方 API。
- 不读取或输出 `.env`、私钥、证书、访问令牌、密码、云凭据和个人数据文件内容。
- 日志、配置和测试数据可能包含 IP、用户名、设备标识、内部地址或密钥；引用前先脱敏。
- 不将模型权重、数据集、录屏、bag、数据库、固件镜像等大文件作为普通文本读取。
- 如果用户明确要求联网查公开资料，只搜索公开的算法/产品/标准信息，不上传私有源代码。

## 2. 文件范围

默认忽略 `.git/`、缓存、虚拟环境、构建输出、安装目录、依赖下载目录和生成代码目录。第三方源码可以在依赖关系中说明，但不应与第一方代码混为一谈。

如果忽略目录可能包含项目自有修改，先检查 Git submodule、vendor 说明或构建配置，再决定是否纳入。不能仅凭目录名判定第三方。

## 3. Git 与文件修改

完整分析和面试模式只读。执行命令前区分只读命令与可能写文件的命令。不得执行 `git reset --hard`、`git clean -fdx`、批量删除、覆盖配置或未经授权的格式化。

代码注释模式原地编辑前检查 Git 状态。用户已有未提交改动的文件不得被覆盖；如果目标文件本身有用户改动，应保留并只做最小注释变更，无法保证时先询问。

## 4. 增量更新

优先使用 Git 比较上次分析的基准提交与当前 HEAD。记录新增、修改、删除、重命名文件。若没有可靠基准，使用扫描清单和内容哈希辅助比较，但不能把哈希变化直接解释成语义变化。

更新步骤：

1. 识别变化文件和变更类型。
2. 读取变更内容及其直接调用者、被调用者、接口定义和配置。
3. 判断是否影响模块职责、执行顺序、数据格式、参数、部署或测试。
4. 更新受影响的文档段落和图表。
5. 检查引用路径、行号、类名、函数名是否仍有效。
6. 在 `10_分析覆盖与待确认项.md` 记录本次基准、变更范围、重分析范围和遗留风险。

不要仅因为某个源文件变更，就无差别重写全部文档；也不要只改文件索引而忽略它对架构和面试知识的影响。
